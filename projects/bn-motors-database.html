Overview01

This project models a multi-store dealership’s operations end to end and shows the full data lifecycle: conceptual modeling, schema design, query optimization, and business intelligence, the kind of practical database work an analyst or data scientist is actually asked to do.

The schema02

The bn_motors database (MySQL 8, InnoDB) is organized into three domains, documented with an ERD and a business-rules blueprint:

  1. Sales. Store, Employee, Customer, Vehicle, Sale, Trade-In, FinanceContract.
  2. Service. ServiceOrder, ServiceLineItem, Technician, Part, Supplier.
  3. Support. Lead, Appointment, Payment, Warranty, VehicleTransfer.

Analytics03

Four analytical modules turn that structure into decisions: inventory (aging, days-in-stock buckets, value by location), sales (gross-profit attribution, salesperson rankings, month-over-month trends, finance penetration), customer (lead-to-sale funnel, lifetime value, segmentation), and a set of reusable reporting views so non-technical stakeholders get standardized metrics without writing SQL.
