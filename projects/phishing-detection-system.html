Overview01

URL-based machine learning is fast, but on modern, JavaScript-heavy sites it tends to over-alert, flagging legitimate pages as threats. This project resolves that by pairing an ML triage step with a deterministic evidence review, so every verdict is corroborated across multiple independent signals and comes with a reason a security analyst can read.

The result is a deployment-ready dashboard that returns a clear safe, suspicious, or phishing decision rather than an opaque score.

How it works02

A URL flows through five coordinated layers before a verdict is issued:

  1. ML + model agreement. A primary model scores the URL, while a witness ensemble (logistic regression, random forest, XGBoost, LightGBM) votes for agreement or disagreement to raise confidence.
  2. Live capture with Playwright. The page is actually loaded to collect final URLs, redirect chains, cross-domain form targets, and TLS / certificate state.
  3. HTML / DOM and behavior. Structural tells are analyzed: wrapper pages, interstitials, credential-harvest layouts, and network patterns that hint at exfiltration.
  4. Brand and trust context. Deterministic matching checks brand-to-domain coherence against a registry used as a weak prior, never a whitelist.
  5. Evidence Adjudication Layer. A deterministic engine weighs all of the above into one of three verdicts, returning uncertain rather than guessing when signals conflict.

Design decisions03

Deterministic at runtime. No external AI is called when scoring a live URL, so verdicts are reproducible, auditable, and free of API latency, cost, and vendor lock-in.
Conservative by default. When evidence disagrees the system says uncertain and defers to a human, prioritizing catching real threats over forcing a clean-looking answer.
